# ChatGPT 桌面派发

> 状态：**调研完成。聊天、工作、Codex 的文字、图片、文件、停止都已在这台 Mac 上点通，可以按本文方案写驱动。生产代码还没写。**
> 日期：2026-10-11
> 机器：这台 Mac Mini。应用 `/Applications/ChatGPT.app`，版本 `26.1007.30912`，包名 `com.openai.codex`。调试口 `127.0.0.1:9334`。Cursor 仍占 `127.0.0.1:9222`。

---

## 0. 结论

派发目标是这台机器上当前可见的 ChatGPT 窗口。它不是文件夹工作区，不是 Codex CLI，也不是模型 HTTP 接口。

| 项 | 结论 |
| --- | --- |
| 能不能派 | 能。文字进当前输入框，点发送后输入框被清空。 |
| 图片和文件 | 能。三条表面的入口不同，见 §2.4。发送前必须看见芯片，发送后输入框里的芯片消失。 |
| 停止 | 能。聊天等按钮可点后用指针点中心。Codex 和工作对「停止」按钮调用 `click()`。 |
| 读回 | 能读到可见对话里的「你说」和「ChatGPT 说」，生成过程中能读到已经出现的正文片段。没有工具轨迹。 |
| 中台现在能不能派 | 不能。`hub` 的 `create()` 仍要求目标文件夹已在 Cursor 里打开，否则 `WORKSPACE_NOT_OPEN`。ChatGPT 没有这把钥匙。 |
| 下一步 | 先放一组会失败的夹具，再写独立驱动。不放进 `extension/src/cdpInject.ts`。 |

账户剩余用量当时是 100%，周期到 11 月 10 日。设置里没有自定义 Base URL。桌面端不能改成走 TokenHub。密钥没有写入应用，也没有写入仓库。

## 1. 调研问题

| 问题 | 调研结果 |
| --- | --- |
| 当前工作区是什么 | ChatGPT 没有 Cursor 那种文件夹工作区。目标就是这台机器上当前可见的窗口。 |
| 怎么派到不同项目 | 项目是输入框上的芯片，不是侧栏那一行。侧栏点项目名，或点「在 middleware 中开始新聊天」，项目下仍是「暂无聊天」。工作芯片是「更改项目：middleware」，Codex 芯片是「切换项目：middleware」。芯片已经是该项目时，发送后的对话出现在侧栏该项目下面。 |
| 中台怎么区分派发 | 不能把项目名塞进 `workspace_root`。目标字段是模式（ChatGPT 或 Codex）加上可选的项目芯片名。没有项目芯片，就用当前这个输入框。 |
| 结果怎么回到中台 | 从可见页面读「你说」之后的正文。图片看「用户附件」，文件看文件名。没有 `conversation_id`、`generation_id`，也不能用 Cursor 的 jsonl。不要用 prompt 文本判断这轮是否结束。 |
| 聊天、工作、Codex 怎么切换 | 模式菜单文案是「切换模式，当前模式：ChatGPT」或「当前模式：Codex」。菜单项是「ChatGPT 创建、学习和探索」和「Codex 构建、调试和发布」。这个菜单要用指针点击打开，对按钮调用 `click()` 打不开。ChatGPT 里面还有「聊天」和「工作」。 |
| 执行过程能不能读 | 生成中能读到「ChatGPT 正在回应」和已经写出的正文片段。结束后能读到完整的「你说 / ChatGPT 说」。没有可展开的思考步骤或工具调用。 |

输入框名字：聊天是「询问 ChatGPT」，工作是「使用 ChatGPT Work」。Codex 新对话先是「随心输入」，发送后变成「与 Codex 协作」。

## 2. 真机证据

### 2.1 拉起

启动合同与 `scripts/armada-cursor.sh` 相同。进程已在跑时，参数会被单实例吞掉。必须先完全退出，再用 LaunchServices 拉起，不用 `open -n`。

```text
open -a "ChatGPT" --args --remote-debugging-port=9334 --remote-debugging-address=127.0.0.1
```

就绪：`127.0.0.1:9334/json/version` 有响应，并且 `/json/list` 能列出 `app://-/index.html`。进程在、端口关，派发失败。不改派 Cursor，不改走 CLI。主页面之外还有一个 detached window，以及 `cdn.platform.openai.com` 上的 runner iframe。驱动只操作 `app://-/index.html`。

### 2.2 过关标准

| 动作 | 过关证据 |
| --- | --- |
| 文字 | prompt 进入当前可见输入框，点发送后输入框被清空 |
| 图片 / 文件 | 发送前可见芯片。图片是预览，文件是移除按钮。发送后输入框里的芯片消失 |
| 停止 | 这轮不再写出完整助手回复。聊天是按钮从禁用变为可点后再点。Codex 和工作是调用 `click()` 后出现「你在 0秒 后停止了」 |
| 读回 | 结束后能从可见对话读到「你说」和「ChatGPT 说」 |

看见控件不算过。写路径要看到那个控件真的被关掉：输入框变空，或者这一轮不再继续写。

探针文件在 `/tmp/armada-probe.png`（1×1 PNG）和 `/tmp/armada-probe.txt`（内容 `hi`）。它们不在仓库里。

### 2.4 三条表面的附件入口

聊天的附件在输入框同一张表单里的隐藏 `input[type=file]`。「添加照片」接受图片，「附加文件」接受任意文件。`DOM.setFileInputFiles` 要先 `DOM.enable`、`DOM.getDocument`、`DOM.requestNode`。`DOM.describeNode` 给出的 nodeId 不能直接用来设文件。文件还在「正在上传」时，发送按钮是禁用的，这时不能再打一遍字，也不能点发送。

工作和 Codex 不能靠这套隐藏输入。工作里的「添加文件等内容」打不开菜单。

工作的入口是工具栏按钮，无障碍名是「文件」。指针点击后，菜单里的最近文件是 `menuitemcheckbox`，另有「浏览全部」。选中后出现「正在上传」和移除芯片。等上传结束、发送可点，再插入文字并发送。这一版只点通过菜单里已经出现的最近文件。

Codex 新对话没有「文件」按钮。加号菜单第一项是「文件和文件夹」，内部动作名是 `context-action:pick-local-files`。点它会关掉菜单。页面没有弹出 Chromium 文件选择，也没有芯片。在菜单里搜 `armada-probe` 只出现旧聊天，找不到 `/tmp` 里的探针文件。能挂上附件的是把文件拖进输入框：`Input.dispatchDragEvent` 依次发 `dragEnter`、`dragOver`、`drop`，`files` 带本机路径。芯片出现并且发送可点之后，再插入文字并发送。

### 2.5 停止和读回

聊天的「停止」一出现时 `disabled` 和 `aria-disabled="true"` 都是真，大约 1.5 秒。这段时间点击无效。可点之后再用指针点按钮中心，雨诗那一轮没有助手结论。点得太早的海诗后来写完了，那一次不算停止。命中点经常是按钮里面的 `svg`。

Codex 和工作的「停止」出现时就已经不是禁用。对按钮调用 `click()` 会停掉这一轮，页面留下用户句和「你在 0秒 后停止了」。指针点 Codex 的停止图标不会停，雨和风那两轮诗都写完了。Codex 按钮的点击处理是 `e=>{if(P){e.preventDefault();return}b?.(e)}`，图标本身是 `svg` 里的 `path`。

进行中能读到的是助手正文片段，以及「ChatGPT 正在回应」。结束后能读到完整的「你说 / ChatGPT 说」。没有可展开的思考步骤或工具调用。

## 3. 解决方案

驱动单独写，不放进 `extension/src/cdpInject.ts`，不把 ChatGPT 的选择器写进 Cursor composer。

中台现有的 `机器|文件夹路径` 不能表示这个窗口。`hub/src/runs.ts` 的 `create()` 在文件夹不在 `open_workspaces` 里时返回 `WORKSPACE_NOT_OPEN`。接 ChatGPT 时要另给目标，不要复用这三把 Cursor 钥匙：窗口加工作区、`conversation_id`、`generation_id`。

落地范围只包括这台 Mac 上已经点通的表面：

1. 拉起：本机脚本，端口固定 9334，只绑 `127.0.0.1`。先完全退出，再 `open -a`，不用 `open -n`。端口没起来就失败。
2. 目标：当前可见窗口。字段是模式（ChatGPT 或 Codex）和可选的项目芯片名。没有项目芯片就是当前这个输入框。
3. 聊天文字：聚焦「询问 ChatGPT」，`Input.insertText`，点「发送」，确认输入框变空。
4. 聊天图片：对同一输入框里的「添加照片」文件输入调用 `DOM.setFileInputFiles`。发送前必须看见预览和移除按钮。看不见就不发送。
5. 聊天文件：对「附加文件」同样设置文件。等到没有「正在上传」，并且「发送」可点，再发送。
6. 工作和 Codex 文字：先用指针把模式菜单切到目标，工作还要点「工作」。项目以输入框芯片为准。然后同样插入文字并发送，确认输入框变空。
7. 工作图片和文件：指针点工具栏「文件」，再点最近文件那一行（`menuitemcheckbox`）。看见移除芯片、没有「正在上传」、并且「发送」可点，再插入文字并发送。发送后输入框里的芯片必须消失。
8. Codex 图片和文件：对「随心输入」发拖放事件，`files` 用本机路径。同样等到移除芯片出现且「发送」可点再发送。不要点「文件和文件夹」，那一下不会挂上芯片。
9. 停止：轮询「停止」，直到它可见并且不再禁用。聊天用指针点按钮中心。Codex 和工作调用这个按钮的 `click()`，不要用指针点图标。点完后按钮不再是「停止」，页面出现「你在 0秒 后停止了」或这轮没有助手正文。禁用期间点击不算停止。
10. 读回：从可见页面读「你说」之后的正文。生成中可以读到已经出现的片段。图片读回看「用户附件」，文件读回看文件名。没有工具轨迹就不编一条。

失败就失败。不改派到 Cursor，不改走 `codex exec`，不调用 Responses API，不读 `~/.codex`，不保存登录态。窗口上没有可提交的输入框，派发失败。

实现顺序：先放一组会失败的夹具，夹具形状跟上面的真机证据一致，再写独立驱动。测不红，不准改生产。

## 4. 这一版不做

- 把桌面端改成 TokenHub 或其它 Base URL。设置里没有这个入口。
- 用文件夹路径、jsonl、`conversation_id`、`generation_id` 描述这个窗口。
- Windows。这台机器的选择器不能拿去宣称 Windows 已过。
- 一次两张图、图片和文件一起发。
- 从「选择项目」或「不在项目中工作」点进另一个项目。芯片已经是目标项目时的发送过了，切换芯片这一下还没单独验。
- 工作区附件走「浏览全部」去选一个不在最近列表里的路径。
- Codex 和「工作」的停止用指针点图标。那条路径已经证明不停。
